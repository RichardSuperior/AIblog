在后端开发领域，选对技术栈往往能让开发效率翻倍。本文将带你用 **Fastify + Prisma + TypeScript** 搭建一套生产级的高性能 API 服务，从项目初始化到路由设计、数据库操作、错误处理，手把手讲透核心要点。

## 一、为什么选择 Fastify 而非 Express？

Express 是 Node.js 生态的老牌框架，但面对现代高并发场景，其性能瓶颈愈发明显。**Fastify** 作为后起之秀，在多项基准测试中吞吐量比 Express 高出 2-3 倍，且原生支持 JSON Schema 验证、TypeScript 类型推断和插件化架构。

> "Fastify 不是 Express 的替代品，而是 Node.js 后端开发的下一个阶段。" —— 社区共识

主要优势对比：

| 特性 | Express | Fastify |
|------|---------|---------|
| 请求/秒（基准测试） | ~15,000 | ~45,000 |
| TypeScript 支持 | 需额外配置 | 原生一等支持 |
| JSON Schema 验证 | 需 middleware | 内置，零额外开销 |
| 插件隔离 | 无 | 有（Avvio 封装） |
| async/await | 支持 | 原生异步 |

对于追求性能和类型安全的团队，Fastify 是 2026 年最值得投入的 Node.js 框架选择。

## 二、项目初始化与目录结构

先安装依赖并配置 TypeScript：

```bash
mkdir fastify-api && cd fastify-api
npm init -y
npm install fastify @fastify/cors @fastify/helmet prisma @prisma/client
npm install -D typescript ts-node @types/node nodemon tsx
npx tsc --init
npx prisma init
```

推荐的项目目录结构：

```
fastify-api/
├── src/
│   ├── app.ts           # Fastify 实例与插件注册
│   ├── server.ts        # 启动入口
│   ├── routes/          # 路由模块
│   │   ├── user.ts
│   │   └── post.ts
│   ├── plugins/         # 自定义插件
│   │   └── auth.ts
│   └── schemas/         # JSON Schema 定义
│       └── user.schema.ts
├── prisma/
│   └── schema.prisma    # 数据库模型
├── tsconfig.json
└── package.json
```

**分层架构**能让路由、业务逻辑、数据访问各司其职，后期维护成本极低。

## 三、Prisma 数据库建模与迁移

Prisma 是目前 Node.js 生态中类型安全性最高的 ORM。定义数据模型（`prisma/schema.prisma`）：

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  posts     Post[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model Post {
  id        Int      @id @default(autoincrement())
  title     String
  content   String?
  published Boolean  @default(false)
  author    User     @relation(fields: [authorId], references: [id])
  authorId  Int
  createdAt DateTime @default(now())
}
```

执行迁移：

```bash
npx prisma migrate dev --name init
npx prisma generate
```

Prisma 会自动生成完整的 TypeScript 类型，包括 `User`、`Post` 等模型类型及所有查询方法的类型推断，**杜绝了 SQL 手写和类型不匹配的低级错误**。

## 四、路由设计与 JSON Schema 验证

Fastify 的亮点在于路由级别的 Schema 验证，既提升了性能（省去 Ajv 手动调用），又能自动生成 API 文档。

`src/routes/user.ts` 示例：

```typescript
import { FastifyInstance } from 'fastify'
import { PrismaClient } from '@prisma/client'

const prisma = new PrismaClient()

const createUserSchema = {
  body: {
    type: 'object',
    required: ['email', 'name'],
    properties: {
      email: { type: 'string', format: 'email' },
      name:  { type: 'string', minLength: 1, maxLength: 50 }
    }
  },
  response: {
    201: {
      type: 'object',
      properties: {
        id:    { type: 'number' },
        email: { type: 'string' },
        name:  { type: 'string' }
      }
    }
  }
}

export async function userRoutes(fastify: FastifyInstance) {
  // 获取用户列表
  fastify.get('/users', async (request, reply) => {
    const users = await prisma.user.findMany({
      select: { id: true, email: true, name: true, createdAt: true }
    })
    return users
  })

  // 创建用户
  fastify.post('/users', { schema: createUserSchema }, async (request, reply) => {
    const { email, name } = request.body as { email: string; name: string }
    
    const user = await prisma.user.create({
      data: { email, name }
    })
    
    reply.code(201).send(user)
  })

  // 获取单个用户
  fastify.get<{ Params: { id: string } }>('/users/:id', async (request, reply) => {
    const { id } = request.params
    const user = await prisma.user.findUnique({
      where: { id: Number(id) },
      include: { posts: true }
    })
    
    if (!user) {
      return reply.code(404).send({ error: 'User not found' })
    }
    return user
  })
}
```

**关键实践**：
1. 将 Schema 定义与路由分离，提升可读性
2. 使用 Prisma 的 `select` 控制返回字段，避免敏感信息泄露
3. 利用 TypeScript 泛型为 `request.params` 提供类型推断

## 五、错误处理与统一响应格式

生产环境必须有统一的错误处理机制，`src/app.ts`：

```typescript
import Fastify from 'fastify'

const app = Fastify({ logger: true })

// 全局错误处理
app.setErrorHandler((error, request, reply) => {
  const statusCode = error.statusCode || 500
  app.log.error(error)
  
  reply.status(statusCode).send({
    success: false,
    statusCode,
    message: statusCode === 500 ? 'Internal Server Error' : error.message,
    timestamp: new Date().toISOString()
  })
})

// 注册路由
app.register(userRoutes, { prefix: '/api/v1' })

export default app
```

通过 `setErrorHandler` 统一捕获所有未处理错误，**线上不会暴露内部堆栈信息**，同时日志系统全量记录，便于排查问题。

4. **生产就绪**：插件化架构、统一错误处理、日志系统，三件套缺一不可
