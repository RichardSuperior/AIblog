## 一、Cursor 的核心差异化优势

Cursor 本质上是一个基于 VS Code 的 fork，但它的核心差异不在编辑器本身，而在于**深度整合的 AI 上下文理解层**。

与 GitHub Copilot 相比，Cursor 最大的优势是：

- **Codebase-aware**：可以理解整个项目结构，而非只看当前文件
- **多模型切换**：支持 Claude、GPT-4o、Gemini 等主流模型，按需选择
- **Composer 模式**：支持多文件、跨文件的批量代码生成与重构
- **@符号上下文注入**：精确控制 AI 能看到哪些信息

## 二、三大核心功能深度解析

### 2.1 Chat 模式 vs Composer 模式

很多人混淆这两个模式，实际上它们适用场景完全不同：

**Chat 模式**（`Ctrl+L`）适合：
- 问技术问题、解释代码逻辑
- 针对单个函数或代码块进行优化建议
- 调试分析：粘贴错误信息，让 AI 给出修复方向

**Composer 模式**（`Ctrl+I`）适合：
- 生成新功能模块（跨多个文件）
- 大规模重构现有代码
- 按需求文档自动生成完整的 CRUD 接口

实战建议：**先用 Chat 确认思路，再用 Composer 批量执行**，这是效率最高的搭配。

### 2.2 @符号：精确控制 AI 上下文

这是 Cursor 最被低估的功能之一。在对话框中输入 `@` 可以注入各种上下文：

```
@文件名.ts         → 注入指定文件内容
@文件夹/           → 注入整个目录结构
@docs              → 注入项目文档
@web               → 让 AI 联网搜索最新信息
@codebase          → 全量索引项目代码
```

**高阶用法示例**：

```
@api/routes.ts @types/user.ts 
请根据这两个文件，为用户模块新增一个支持分页的列表查询接口，
返回格式与现有接口保持一致
```

这比直接说"给我写一个列表接口"精准得多，AI 输出的代码几乎可以直接使用。

### 2.3 Rules for AI：定义团队编码规范

`.cursorrules` 文件是 Cursor 的隐藏神器。在项目根目录创建该文件，可以持久化注入编码规范：

```
# .cursorrules

你是一个资深 TypeScript 全栈开发者。

## 代码规范
- 所有函数必须有 JSDoc 注释
- 使用 async/await，禁止 .then() 链式调用
- 错误处理必须使用 try/catch，不允许吞掉错误
- 变量命名使用驼峰命名法，常量使用全大写

## 技术栈
- 前端：React 19 + TypeScript + Tailwind CSS
- 后端：Fastify + Prisma + PostgreSQL
- 测试：Vitest + Testing Library

## 输出要求
- 每次修改后说明变更内容
- 给出可能的性能优化建议
```

有了这个文件，团队所有成员使用 Cursor 时，AI 的输出风格会自动对齐，**代码 review 时的风格分歧会大幅减少**。

### 3.1 需求驱动开发（PRD → Code）

2026年流行的 Vibe Coding 工作流在 Cursor 中可以这样落地：

1. **准备需求文档**：在项目中创建 `docs/PRD.md`，写清楚功能需求
2. **Composer 注入**：`@docs/PRD.md 请按照需求文档实现用户登录模块`
3. **分步确认**：先让 AI 列出实现计划，确认后再执行
4. **测试生成**：`@src/auth/ 为刚才生成的代码编写单元测试`

这套流程让需求到代码的转化效率提升 3-5 倍，且代码质量有保障。

### 3.2 Legacy 代码重构的最佳实践

面对遗留代码，Cursor 的处理策略要有所不同：

```
Step 1: @legacy/old-module.js 
请分析这段代码的功能、潜在问题和技术债务，
输出分析报告，不要修改代码

Step 2: 基于分析报告，列出重构计划和优先级

Step 3: 逐步执行重构，每次只改一个功能点
```

**切忌让 AI 一次性重写整个模块**——这是踩坑最多的操作，往往引入新问题的速度比解决旧问题的速度更快。

### 3.3 模型选择策略

Cursor 支持多种模型，如何选？按场景来：

| 场景 | 推荐模型 | 原因 |
|------|---------|------|
| 复杂架构设计 | Claude Opus | 推理能力强，代码逻辑严密 |
| 日常代码生成 | GPT-4o / Claude Sonnet | 速度快，性价比高 |
| 前端 UI 生成 | Claude Sonnet | HTML/CSS 生成质量最好 |
| 快速补全 | cursor-small | 延迟最低，适合高频输入 |

## 四、常见误区与避坑指南

**误区一：把 Cursor 当搜索引擎**
Cursor 最大的价值是**生成+重构**，而不是回答"这个 API 怎么用"。查 API 文档直接用官方文档更快。

**误区二：不给上下文就要求生成**
"帮我写一个登录功能"这种 prompt 质量很低。高质量 prompt 应该包含：技术栈、已有代码、期望接口格式、特殊约束。

**误区三：无脑接受 AI 输出**
AI 生成的代码**必须 review**，尤其是涉及权限控制、数据库操作、支付逻辑等安全敏感场景。Cursor 的价值在于提速，不在于替代思考。

**误区四：忽略 Tab 补全的威力**
Cursor 的多行 Tab 补全基于当前上下文预测，当你开始写一个模式时（比如 if 判断、try/catch），连续按 Tab 往往能补全整段逻辑，效率远超手打。
